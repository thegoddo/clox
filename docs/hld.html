High-level design

clox is a bytecode interpreter for the Lox language, written in C while following Crafting Interpreters (Part III). Source goes in; a compact bytecode program is produced; a stack VM executes it.

Where you are: chapter 19 complete You have finished chapter 19 – Strings (fixes to match the book are in the working tree, not yet committed). The language is still a calculator: one expression per line (numbers, booleans, nil, string literals, - ! + - * / == != < <= > >=, with + also concatenating strings). There are no statements or variables yet.
It builds cleanly with gcc (-Wall -Wextra -std=c11; the only warning is the book's unused oldSize in reallocate) and passes the smoke tests in the LLD.

Architecture

Everything is single-pass: there is no AST. The compiler pulls tokens from the scanner one at a time and writes bytecode into a Chunk as soon as it recognises each construct. The VM then walks the chunk with an instruction pointer, using a value stack for operands.

Life of one REPL line

  1. main.c prints > , fgets a line, calls interpret(line).
  2. interpret (vm.c) creates an empty Chunk and calls compile(source, &chunk).
  3. The compiler initialises the scanner, advances to the first token, parses one expression(), expects EOF, emits OP_RETURN. Syntax errors are printed to stderr and flip hadError.
  4. If DEBUG_PRINT_CODE is on and there was no error, the chunk is disassembled to stdout.
  5. On success, the VM sets ip to the first byte and runs run(): constants are pushed, operators pop operands and push results.
  6. OP_RETURN pops the final value, prints it, returns INTERPRET_OK. The chunk is freed and the REPL loops.

Key design decisions

Bytecode VM, not tree-walker
Compact, cache-friendly, fast dispatch; the cost is a compiler step.
Pratt parser, no AST
One table (rules[]) drives all expression parsing and precedence — adding an operator is one table row.
Stack-based VM
Operands implicit on a stack → short instructions, trivial codegen.
Pull scanner + trie keywords
No token array; keyword lookup with a hand-rolled trie — zero allocation.
Tagged-union values
16-byte Value (bool / nil / number / heap-object pointer); no coercion; only nil and false are falsey.
One allocator
reallocate() is the sole heap gateway, so a future GC can count bytes.
Intrusive object list
Every heap object starts with an Obj header whose next links it into vm.objects; freeVM() walks that list. This is the groundwork for the GC.

Language supported today

expression → equality
equality   → comparison ( ( "!=" | "==" ) comparison )*
comparison → term ( ( ">" | ">=" | "<" | "<=" ) term )*
term       → factor ( ( "-" | "+" ) factor )*
factor     → unary ( ( "/" | "*" ) unary )*
unary      → ( "!" | "-" ) unary | primary
primary    → NUMBER | STRING | "true" | "false" | "nil" | "(" expression ")"

Identifiers, and/or, print, var, blocks etc. are tokenised but have no parse rule (rules[] entry is {NULL, NULL, PREC_NONE}), so they give Expect expression.

Build, tooling & conventions

  • Build: make (format → gcc -Wall -Wextra -std=c11) → ./clox. Run with no args for the REPL or ./clox file.lox.
  • Formatting: clang-format, 80 cols, 2-space indent. make check-format mirrors the pre-commit hook (hook only active if git config core.hooksPath .githooks — currently unset).
  • Debug flags in common.h: DEBUG_PRINT_CODE (disassemble after compile), DEBUG_TRACE_EXECUTION (per-step stack + instruction trace).
  • Exit codes: 64 usage · 65 compile error · 70 runtime error · 74 I/O.
  • No tests exist yet.
