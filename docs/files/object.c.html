object.c

Allocates heap objects and interned strings (copyString / takeString); FNV-1a hashString; printObject.

Data70 linesincludes: stddef.h, stdint.h, stdio.h, string.h, memory.h, object.h, table.h, value.h, vm.h

What it does

Creates objects. allocateObject asks reallocate for size bytes, sets the type tag, and pushes the new object onto the head of vm.objects. allocateString wraps that for ObjString, stores the precomputed hash, and registers the new string in vm.strings (the intern set: key = the string, value = nil). copyString duplicates a character range (adding the NUL) — used for literals, since the source text is freed after compiling. takeString adopts a buffer the caller already allocated — used by concatenation, avoiding a second copy.

Interning (chapter 20): both constructors first hash the characters and call tableFindString. If an identical string already exists it is returned instead of making a new one — copyString simply skips the copy, takeString frees the buffer it was handed. So every distinct string exists exactly once, and equality is a pointer compare.

Things to remember

  • Order matters: allocateString is static and has no prototype, so it must be defined above its callers.
  • All strings are interned, so valuesEqual compares Obj* pointers — no memcmp.
  • takeString frees the caller's buffer when the string is already interned. Never touch the buffer after calling it.
  • The hash is computed once at creation and cached in ObjString.hash; the table never re-hashes characters.
  • When the GC arrives (chapter 26), the new string must be kept reachable (pushed on the stack) around tableSet, because growing the table can trigger a collection.
