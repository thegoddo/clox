table.c

Open-addressing hash table: linear probing, tombstones, 75% load factor, string lookup for interning.

Data133 linesincludes: stdint.h, stdlib.h, string.h, memory.h, object.h, table.h, value.h

What it does

A hash table with open addressing and linear probing: entries live directly in one array; on a collision the next slot is tried, wrapping around. The bucket is key->hash % capacity, using the hash cached in the ObjString. The table grows (×2, minimum 8, via GROW_CAPACITY) when count + 1 > capacity × 0.75; growing re-inserts every live entry into a fresh array, dropping tombstones.

Deletion uses tombstones: a deleted slot becomes key = NULL, value = true rather than truly empty, so probe sequences that pass through it keep working. A truly empty slot is key = NULL, value = nil.

What's in it

SymbolMeaning
TABLE_MAX_LOAD0.75.
findEntryStatic. Probe from the bucket; return the matching entry, or the first tombstone seen, or the empty slot that ended the probe (so inserts reuse tombstones).
adjustCapacityStatic. Allocate a new nil-filled array, re-insert live entries, recompute count (tombstones dropped), free the old array.
tableSetGrow if needed; count++ only when filling a truly empty slot (re-using a tombstone keeps the count).
tableGet / tableDeleteEarly-out on an empty table, then findEntry.
tableAddAllLoop + tableSet.
tableFindStringLike findEntry but compares length, hash, then memcmp. Used by copyString/takeString to intern.

Things to remember

  • tableDelete does not decrement count: tombstones count toward the load factor, which guarantees there is always an empty slot and probing terminates.
  • Key comparison in findEntry is pointer equality — only valid because strings are interned.
  • capacity is a power of two in practice, but the code uses % (the book's chapter-30 optimisation switches to a bit mask).
